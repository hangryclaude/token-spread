The image trick works. It just doesn't win.

Rendering text as an image to survive /compact buys 2.07× at 93.9% recall — measured blind, not cited. Delegating the same job to a subagent buys 20–100× and corrupts nothing. Here is the measurement, the cliff nobody mentions, the result that a blind re-run overturned, and nine corrections to the register we already published.

The measurement

Two corpora — dense code, and real English prose — each packed to fill the page, with hex probe codes embedded at a fixed interval. Scored by exact string match after reading the PNG back through Claude Code on Opus 5, a different instrument from the one that drew it.

Read row 1 against row 2. Same font, same ratio, recall goes 94% → 30%. The variable isn't Claude's eyesight and isn't the compression — it's whether the image got resized in transit.

Claude Code downscales anything over 2000 px. Send the API's 2576 px maximum "for quality" and every glyph is multiplied by 0.776 before Claude sees it. You pay for 4,784 visual tokens and get the legibility of 2,952. Oversizing loses on both axes at once.

Row 3 is the one I got wrong first. Prose at the same 9.3 px scored 97% on the first run, which looked like proof that English redundancy rescues identifiers. It wasn't. That page shared a random seed with a page I'd already graded, so I was recalling the answers, not reading them. Re-run blind on fresh seeds: 32% and 43% — indistinguishable from code.

Failure one: single-glyph errors

Between a quarter and three-fifths of wrong probes are wrong by exactly one character. Not garbled — plausible:

95798d→05798d
f60f3b→f68f3b
b3d0cb→b3d8cb

Failure two: association drift — the worse one

The most damaging error isn't a misread glyph at all. It's reading a value correctly and filing it under the wrong key. Probe 0104's code 943c2b was transcribed perfectly — and attached to probe 0096. Two probes scored wrong, zero characters misread.

A one-character error in a hash, key, SHA, port or version passes every human review and every LLM review. A correctly-read value filed under the wrong key passes character-level checks too. Truncated-summary loss is loud. Optical loss is silent.

It also means per-character accuracy is the wrong metric: at 9.3 px it reads 67–79% while exact probe recall is 30–43%. Report probe recall — character accuracy is the number that makes this technique look survivable.

The rule stands, and the blind re-run strengthened it: gist through images, never identifiers. Diagrams, UI screenshots, chart shapes, "does this look right" — fine. Anything you intend to run, paste, or compare — never.

Which failure mode actually breaks it

Every wrong probe, classified by whether the code it transcribed appears anywhere in ground truth. If it does, the glyphs were read correctly and only the key binding failed.

I called drift the dominant failure. It isn't — 4 errors of 60. Glyph error is 56. Read-anywhere is the ceiling if keying were free: at 9.3 px it's still only 30–48%. Delivered pixel size is the whole game.

Drift still earns its place for one reason unrelated to frequency: it is the only error class no character-level check can catch. A checksum over the transcription passes. Only the key→value binding is broken. It appeared solely on prose pages, where probes sit 40 words apart — suggestive of visual distance as the cause, but untested.

A defect the audit turned up in our own code

Checking the site against the nine corrections found something worse than a stale doc.

WhereSaidActual, to 31 Aug 2026
src/rates.tsSonnet 5 $3/$15$2/$10

rates.ts notesalready said intro pricing was in force — the note and the number disagreed

A rate card is a snapshot. Pricing tomorrow's rate today over-states Sonnet 5 cost by 50% — and over-states every saving measured against it by the same margin. That is the exact overclaim this whole project exists to prevent, shipped in our own core.

On your traffic it's ~$1, because Sonnet is 0.25% of your spend. On a Sonnet-heavy customer it is a 50% inflated baseline. Fixed, plus a new lapses field so a card that is two days old but already wrong says so out loud:

Report warning, today
! in 21 days, on 2026-09-01: claude-sonnet-5 rises from $2/$10 to $3/$15 per MTok (a 50% increase)

No test caught it because none asserted a dollar value — only that rates were integers and that the cache multipliers divided exactly. Five tests added, including one that fails if any rate in a card post-dates the card's own capture date.

Still open

  • How much of the 9.3 px failure is drift rather than glyph error? Drift appeared in two of three blind passes and is the more dangerous mode, because the value read is correct. Scoring position-independent recall against keyed recall isolates it.
  • What is actually billed on a client downscale? 2576 px in, 2000 px delivered — 4,784 visual tokens or 2,952? count_tokens settles it.
  • Does compaction's sampling step get the cache discount? 180,000 input tokens at full price versus 0.1× is the difference between compaction being cheap and being the largest line on the bill. The docs are silent.
  • Where on the page do errors concentrate? The rig scores recall but not position. If they cluster at the edges, the fix is layout, not font size.

Rig: bench/optical/ — headless Chrome, seeded corpus, page packed by construction, exact-match probe scoring. Graded on Claude Opus 5 through Claude Code's Read. One grader, one pass per page, so intervals are wide — treat the boundaries, not the point estimates, as the result. Grader variance is itself large: a rushed pass and a careful pass on comparable pages gave 32.1% and 42.9%.

Retracted: the two 97% figures above. Both pages shared a random seed with a page already graded, so both were recall rather than reading. The rig now documents a one-seed-one-graded-page rule, because that mistake produced a confident, wrong, and very quotable headline.

DeepSeek-OCR's 10× / 97% and Glyph's 3–4× are cited as what those papers measured on their own models, never as Claude figures. The measured Claude ceiling is 2.07×.
