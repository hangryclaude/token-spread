# Sweep 13 — ten axes, and a challenge that ran both ways

**226 entries · 71 pass · 43 on the provider's word · 66 rejected · 46 unresolved.**

called that out on 2026-08-17: the bias check ran one direction, so a verdict that was too harsh
had no way to be found. This sweep fixed it. Passes got **two independent refuters** with
different lenses — one on mechanism, one on evidence. Rejections and unresolveds got an
**advocate** arguing they were judged too harshly, defaulting to upholding.

## What the challenge changed, and why it mattered

**Three rejections were wrong, and only an advocate could have found them.**

*Claude's text watermark* was adjudicated `FAIL` on the reasoning that "a different mechanism
decides what gets produced." That sentence is not in the bar. The bar is a three-part
disjunction — different tokens read, different model answering, different amount of thinking —
and swapping a keyed PRF for an RNG at the sampling step trips none of them. The adjudicator had
substituted a broadened restatement of the standard for the standard itself, which is the exact
failure this register polices in *sources*. It sits at `CONTRACTUAL_ONLY` because the
no-quality-impact claim is Anthropic's, and its supporting measurement is Google DeepMind's on
Gemini traffic (SynthID-Text, Nature 2024), not anyone's on Anthropic's deployment.

*Google Cloud Tasks task-ID dedup* was failed as a blanket claim and is true as a narrow one —
where the task ID is a hash of the request body rather than a business identifier, the duplicate
task is never created and no request is ever sent. Scoped in its own title, on the pattern set by
the K8s CronJob Forbid entry at id 187.

*Claude Code Routines billing* moved off the fence because the advocate read a documentation page
the adjudication never cited.

**Five of six passes did not survive.** The one that did — Anthropic's $50,000 sales-assisted
invoice threshold — was attacked twice and neither refuter landed.

The demotions rhyme. *Sidekiq Enterprise Unique Jobs* was passed on the premise that its default
lock key `(class, args, queue)` is content-derived. It is, but Sidekiq's own guidance is to keep
args small — pass identifiers, resolve the real request at execution time — so under the
documented pattern the key is an enqueue-time label and two enqueues sharing it can resolve to
different model requests. That is the same content-blindness that failed BullMQ at id 189,
reached from the opposite direction: not a caller-supplied string, but a content-derived key over
the wrong content.

*The Anthropic SDK non-streaming duration preflight* was passed as a guard against a documented
double-billing failure mode. Both branches key on `max_tokens` — the caller's declared ceiling —
so the token-cap branch fires unconditionally on any request declaring more than the per-model
limit, refusing calls that would have completed. A refused call is not a cheaper call. One of two
refuters landed this; the other upheld the pass, and the source citations reproduced exactly at
the pinned commit either way.

## What the critic found, unedited

**The china-providers axis gave up where another axis did not.** Doubao/Volcano Engine's caching
docs are a client-rendered SPA and the finder concluded a headless browser was out of budget;
Tencent Hunyuan's own cache page was never located. Meanwhile the row-providers axis hit an
identical JavaScript wall on Yandex and solved it with a Wayback Machine snapshot. That fix was
never carried across. Seven of ten named Chinese providers have no quotable primary source here.

**Two entries rest on sources nobody corroborated.** *OpenAI Ultrafast mode* (id 204) rests on a
GlobeNewswire press release as republished by a third-party newspaper, never checked against
openai.com or cerebras.net. *Routines* (id 224) hangs its live-mechanism claim on one anonymous
GitHub issue with no comments and no Anthropic acknowledgement. Both entries say so in their own
`provenance` field, and neither claims a pass — but neither was cross-checked.

**The gateway-layer axis reported three findings and its notes name only what it rejected.** Its
accepted candidates cannot be audited from its own write-up.

**Nobody escalated for an API key.** Four-plus entries sit at `INSUFFICIENT_EVIDENCE` for the
identical reason, and the sweep treated that as a fixed constraint rather than a request.

Three of the critic's findings — the usage-credit-expiry inference, the prefix-staggering prose
outrunning its citation, and Z.ai's unresolved consequence — were independently caught by the
refuters and are already reflected in the verdicts above at ids 212, 201 and 210.

## Nothing here is measured

This sweep ran no traffic. There is no `ANTHROPIC_API_KEY` and there was none for sweep 12's
recovery either. Every conclusion in this cohort is source-derived, every entry says so in its
`provenance`, and anything that would need a measurement to stand carries a
`settlingExperiment` naming it rather than being rounded up.

The items only a live account can settle are unchanged and now number more than four:

1. Whether Batch/Flex/PTU run identical weights and precision.
2. DeepSeek's, Kimi's, StepFun's, Qwen's and Baidu's output-invariance claims — five providers
   now assert it in their own documentation and not one has been independently replayed.
3. Whether Claude Code on a subscription login satisfies the Consumer Terms §3 carve-out (id 198).
4. Who captures a mid-term list-price decrease on the Anthropic half of id 200.
5. Whether Routines bill to metered credits rather than subscription usage (id 224).
6. Whether the SDK's auto-retry-on-timeout double-bills in practice (register id 150, still open).

## The honest sentence

Thirteen sweeps and 226 adjudicated candidates. The newest-surfaces axis is generated by
providers' release cadence rather than by search effort, so "every method possible" remains a
claim with a date on it and today's date is 2026-08-17. What is new this time is not the count:
it is that a verdict in this register can now be overturned in either direction, and eight were.
