Two adjudication traps this sweep surfaced, both now named in their entries:

- **A bot-closed PR is not a fix.** One candidate cited "maintainer-verified" evidence that was
  the unassigned author's own self-report inside a PR auto-closed by a bot. The real fix was a
  different, later PR. Check `state`/`mergedAt`, not whether the quoted text exists somewhere.
- **A CLOSED PR can still be merged.** Spring's contribution flow squash-merges outside GitHub's
  button, so the API reports CLOSED/mergedAt:null for changes that are genuinely on main. The
  adjudicator settled it with `gh api .../compare` ancestry, not the PR state field.

Where the six passes land: the instrument-correction pattern for a fourth major framework
(langchain-core's v3 streaming bridge zeroed cache-token details for every provider), a real
agentic-caching lever (spring-ai never placed a cache breakpoint on tool-result messages, so
every tool round re-paid full price for the growing history — fixed upstream, reporter-verified
on RC1), byte-exact KV-cache persistence for self-hosters (llama.cpp `/slots` save/restore,
Jan's slot pinning), and two eval-replay levers (promptfoo's error-only retry, langsmith's
VCR-cassette test cache). The register's oldest lesson holds at any star count: what survives
the bar is mostly corrections to instruments and placement of metadata — not magic.
