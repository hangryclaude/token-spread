The problem

A broken cache throws no error.

It doesn't crash. It doesn't warn. cache_read_input_tokens quietly goes to zero and your bill goes up. One dynamic field in the wrong place is enough — and nothing in your stack is watching for it.

// healthy — the prefix is being reused
"usage": {
  "input_tokens":              1,204
  "cache_read_input_tokens":   847,392   ← billed at 0.1x
}

// broken — same code, one field moved
"usage": {
  "input_tokens":            848,596   ← full price, every turn
  "cache_read_input_tokens":       0   ← no error, no warning
}

4breakpoints, max

Anthropic allows four cache_control markers per request. Place them wrong and you pay to write a cache nothing ever reads.

20block lookback

A breakpoint searches back only twenty content blocks. Eight parallel tool calls can overshoot that in a single turn — and the whole prefix reprocesses.

512token minimum

Below the model's minimum cacheable prefix, caching silently does nothing at all. No error is returned.
