Methods

One question decides every lever.

There are plenty of ways to make an AI bill smaller. Most of them change what the model gives back. We only turn on the ones that can't.

Ship by default

Same model, same input tokens. There is no quality decision being made, so there is nothing to test and nothing to argue about in a security review.

  • Prompt caching, text and images
  • Exact-match response cache
  • Billing-path selection
  • Cache-write TTL right-sizing

In-flight request dedup used to sit on this list. Our own register rejects it: collapsing N concurrent identical calls onto one forward pass means the second caller receives the first caller's sample rather than an independent draw. Free, and not identical. It was removed on 2026-08-12.

Off unless you ask

Each of these genuinely saves money, and each is your call rather than ours. Most of them change what the model receives or which model answers. The batch API does not — but only Anthropic can vouch for that, and their word is not the same as our proof, so it sits here too. We'll tell you what they'd save. We won't switch them on for you.

  • Batch API for async work — provider's word only
  • Routing to a cheaper model
  • Image downsampling
  • OCR instead of vision
  • Semantic / fuzzy caching
  • Trimming conversation history
  • Output truncation via stop_sequences

The register

184 techniques. 70 survive.

One question decides every one of them: does the model read a different sequence of tokens, does a different model answer, or does a different amount of thinking happen? If the answer is yes it is not a saving — it is a changed product sold as one.

What the adjudication found

  • 70 pass the bar
  • 27 pass on the provider's word alone
  • 51 rejected outright
  • 36 unresolved — stated as unresolved, never counted as savings

Those four add to 184. Nothing is uncounted, because a register that quietly drops a category is doing the thing it exists to prevent.

Each of the 66 is graded by what can be proven about it, strongest first: nothing on the wire changed · only a field the model never reads changed · only when the request was sent changed · a stored response hash-matches a byte-identical repeat. The other 24 have only the provider's documentation that nothing changed, and no way for us to verify it from outside — so they ship opt-in and never by default.

What stays in the audit

Which levers apply to your traffic, in what order, and what each one is worth against your own rate card. That is the audit, and the audit is the product. The register is the standard we hold a lever to — not a how-to.

Two things we will say for free, because they are costing people money right now: the most-recommended cache fix on the internet — take the timestamp out of your system prompt — fails this bar. So does the second, moving static content to the front. Both change what the model reads.

The register carries its own errata. A re-verification pass against primary documentation on 2026-08-11 found nine entries wrong or incomplete — three of them wrong about what the register recommends, not merely about what it states. They are corrected inline and dated. A cost register that has never had to correct itself has not been checked.

Two honest limits. Caching discounts input only; output always bills at full rate, which caps every input-side lever. And inference isn't bit-deterministic to begin with: send the same prompt a thousand times at temperature 0 and you get back around eighty distinct completions, because GPU kernels don't reduce in a fixed order. Nothing on this page causes that and nothing on this page can fix it. So "identical" means zero quality change by construction — same model, same input tokens — not identical bytes. Only an exact-match cache hit is literally byte-for-byte, because it returns what was stored.

Things that sound like savings and are not

ClaimWhat's actually true
Lower max_tokensZero price effect in either direction. You are billed on tokens generated, not on the ceiling you set.
A cheaper image formatNone. Token cost is ceil(w/28) × ceil(h/28) — pixels only. JPEG vs PNG changes upload size and nothing else.
Long-context discount tierDoes not exist on any current model. A 900K-token request bills at the same per-token rate as a 9K one.
Fast modeA 2× premium on Opus, not a discount, and it multiplies with everything else.
Files APINo token reduction. An uploaded image bills exactly as inline base64 does. It is a payload and latency win.
Tiling a big imageCosts more, not less — each tile hits the resolution cap independently. It buys fidelity, not savings.

We publish these because every one of them is something a vendor could quietly bill you for implementing. None of them will appear on your invoice as a saving, so none of them appear in ours.

Why the split matters

Quality-neutral savings don't need a committee.

Anything that changes model output has to be evaluated, argued about, and signed off. That's where cost projects die. Everything in our default set skips that conversation entirely — because nothing about the answer changed.
